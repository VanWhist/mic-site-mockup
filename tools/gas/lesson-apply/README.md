# MIC-Lesson-Apply-API（一般レッスンの申込フォームの受け取り先）

`lesson-apply.html`（ホームページ内の申込フォーム）から送られた申込を、
スプレッドシートに記録し、申込者へ受付メール、運営へ知らせるメールを送る。
任意で送られた滑走動画は、Google ドライブのフォルダに直接届く。

- 定員は自動で締めない（フォーム＋手動で管理する決定）。知らせるメールに、回ごとの申込数を書く。
- 毎朝のまとめメールは作らない（10月の一般レッスンで止めたもの）。申込1件ごとに知らせる。

## 設置の手順（mogul.mic@gmail.com で行う）

1. Google ドライブに、申込用のスプレッドシートを新しく作る（名前の例：MIC一般レッスン申込_雪上2026-27）
2. 動画を入れるフォルダを作る（例：MIC一般レッスン申込_動画）
3. https://script.google.com で新しいプロジェクト「MIC-Lesson-Apply-API」を作り、`Code.gs` の中身を貼る
4. プロジェクトの設定 → スクリプトプロパティに、次を入れる

   | プロパティ | 入れるもの |
   |---|---|
   | `SHEET_ID` | 1 のスプレッドシートの ID（URL の /d/ と /edit のあいだ） |
   | `NOTIFY_EMAILS` | 申込を知らせる先。複数はカンマ区切り |
   | `VIDEO_FOLDER_ID` | 2 のフォルダの ID（URL の /folders/ のあと） |
   | `CONSENT_PDF_ID` | （任意）受付メールに付ける参加同意書 PDF の ID |

   ★ メールアドレスや ID は、このリポジトリ（公開）には書かない。プロパティにだけ置く。

5. プロジェクトの設定で、タイムゾーンを「(GMT+09:00) 東京」にする
   - 左の「サービス」の「＋」から **Drive API** を足す（動画の受け取りに必要。無いと Drive が 403 を返し、動画だけ届かない）
6. 関数 `checkSetup` を選んで実行 → 権限を許可（スプレッドシート・ドライブ・メール送信・外部への通信）
   - 実行ログに「★未設定」が出ないことを確かめる
   - 申込シートに見出しの行ができる
7. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」
   - 実行するユーザー：自分
   - アクセスできるユーザー：全員
8. 出てきた /exec の URL を `data/api-config.js` の `lessonApplyApi` に入れ、PR → マージ

## 試し方（公開前）

- まず関数 `testApplyToMe` を実行する（実行したアカウントあてに、試しの申込を1件通す）
  - 申込シートに「状態：テスト」の行が1行入る／受付メールと知らせるメールが届く
  - テストの行は申込数に数えない
- 関数 `testVideoStart` を実行する（動画の受け取りを始められるかだけを確かめる。ファイルは作らない）
  - 「開始 OK（200）」と出れば合格。403 なら「サービス → Drive API」が足りていない
- `lesson-apply.html?mic_noanalytics=1` を開き、自分のメールアドレスで1件申し込む
  - 受付メールが届く／知らせるメールが届く／申込シートに1行入る
  - 動画を付けて送ると、フォルダに入り、シートの「動画（リンク）」に入る
- フォームから試した行は、シートの「状態」を「取消（テスト）」にする（申込数に数えなくなる）

## 新しい回を受け付けるとき

`Code.gs` の `LESSONS` と、`data/lesson-apply.js` の `lessons` の両方に同じ回を足す。
`Code.gs` を直したら、デプロイ → デプロイを管理 → 編集 → バージョン「新バージョン」で更新する
（新しいデプロイを作ると URL が変わるので、作らない）。

## 申込シートの列

受付日時／受付番号／回の組／参加者番号／申込者氏名／電話番号／メールアドレス／きっかけ／
参加者氏名／ふりがな／年齢（学年）／参加する回／スキー歴／ふだん滑っている斜面／モーグルの経験／
今回やってみたいこと／不安なこと／けが・持病など／加盟団体／MICのレッスン参加経験／
動画（ファイル名）／動画（リンク）／どのカードから／utm／状態／メモ

兄弟・家族でまとめて申し込んだ場合は、参加者1人につき1行（受付番号は同じ）。
